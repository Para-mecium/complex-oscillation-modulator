# Reproducibility Guide

This repository contains the MATLAB implementation and archived data used for
the FMAM modulation examples, network experiments, parameter-inference
experiments, and figure-generation workflows in the manuscript.

The package is organized so that a reader can follow each figure group through
three separate stages:

1. Data generation or loading of archived example data.
2. FMAM modulation, parameter inference, continuation, or repeated simulation.
3. Plotting from the corresponding `.mat` outputs.

Most figure directories include checked-in `.mat` files so that plotting scripts
can be run without recomputing the most expensive sweeps. Re-running builder
scripts may overwrite those data files.

## Quick Start

From the repository root:

```matlab
addpath(genpath(pwd))
```

Run the regression tests:

```matlab
test/run_tests
```

Run a representative plotting workflow from archived data:

```matlab
Longevity/draw_etd_fig2c
Longevity/draw_etd_fig2d
Longevity/draw_etd_fig2e
```

For figure-specific scripts, see `FIGURE_WORKFLOW_MAP.md`.

## Repository-Level Workflow

The main script prefixes are used consistently:

- `build_*_data.m`: generate or regenerate `.mat` data for a figure panel.
- `run_*.m`: execute a modulation, parameter-inference, baseline, or sweep task.
- `reproduce_*.m`: reproduce a collection of panels from archived sweep data.
- `draw_*.m` / `plot_*.m`: generate figures from already saved data.
- `test/test_*.m`: validate public interfaces and representative workflows.

The scientific core is shared across these workflows:

- `FMAM_ODE.m`: continuation solver for modulation paths.
- `state.m` and `fmam_state_ops.m`: periodic-orbit state representation and
  adapters.
- `build_symbolic_derivatives.m`: optional symbolic derivative cache builder.
- `solve_generic_newton.m` and `solve_regularized_linear_system.m`: numerical
  linear and nonlinear solver support.
- `PO_extract/`: periodic-orbit extraction utilities and I/O contract.

## Expensive Recomputation Policy

Some figure panels come from repeated stochastic simulations, network sweeps, or
baseline optimization runs. For those panels, the repository includes archived
intermediate `.mat` files where available. The draw scripts should be treated as
the fastest verification route, while the corresponding `build_*` or `run_*`
scripts document how the archived data were generated.

When fully regenerating a workflow, run builder scripts before draw scripts. The
builder scripts are not optimized as short demonstrations; some require parallel
workers or long runtimes.

## Tests

The main test entry point is:

```matlab
test/run_tests
```

The tests cover state adapters, Newton assembly, periodic-orbit extraction
contracts, data-driven circuit regression, SDE utilities, and representative
figure-data workflows.
